# Заочное отделение · Лабораторные работы

Заочный вариант курса: один лекционный день из двух пар и две лабораторные работы. Здесь правила сдачи, остальное в заданиях.

## Две работы

| № | Тема | Пара | Срок |
|---|---|---|---|
| 1 | [Языковая модель из счетчиков и свой токенизатор](assignments/01/README.md) | 1 | две недели после лекций |
| 2 | [Свой трансформер: обучение и генерация](assignments/02/README.md) | 2 | четыре недели после лекций |

Работы связаны: во второй трансформер учится на токенах BPE, который вы напишете в первой, и сравнивается с моделью из счетчиков оттуда же. Делайте их по порядку. Корпус у обеих один, «Война и мир», скрипты скачивают его сами.

Занятия по работам ведет лаборант. На занятии по первой работе: вопросы по репозиторию и окружению, разбор задания, устная проверка тех, кто уже сдал. На занятии по второй работе: разбор и прием второй, прием первой у опоздавших. Точные даты в расписании.

## Репозиторий

1. Создайте свой репозиторий из шаблона курса на GitHub (ссылка выдается вместе с заданиями). 
2. Работы живут в папках `pt01/` и `pt02/` в корне репозитория; папки `lab01` … `lab07` это очный трек, их не трогайте. В каждой папке `run.py`, артефакты в `artifacts/` и `README.md`.
3. Данные и веса моделей в репозиторий не кладутся: корпус скачивает скрипт, `corpus.txt` и `*.pt` уже в `.gitignore`. Артефакты работ, наоборот, коммитятся: по ним идет проверка.

## Что значит «работа сдана»

Три условия одновременно.

**CI зеленый.** При каждом push запускаются автотесты по затронутым работам. Они проверяют воспроизводимость, а не качество модели: артефакты на месте, схема файлов верна, числа согласованы между собой, модель лучше случайного угадывания. Тесты всегда берутся из репозитория курса, правки в вашей копии `tests/` на проверку не влияют. Перед push прогоните их у себя:

```
python pt01/run.py --fast && pytest tests/test_pt01.py
python pt02/run.py --fast && pytest tests/test_pt02.py
```

Пока в `run.py` стоит заглушка с `NotImplementedError`, тесты по работе пропускаются, и CI не краснеет.

**Есть отчет.** `README.md` в папке работы из трех разделов, на один экран:

- *Что сделано.* Коротко, по пунктам, без пересказа задания.
- *Что получилось.* Цифры: перплексии, число параметров, время обучения, образцы генерации. Что именно нужно, перечислено в задании.
- *Что не получилось и почему.* Самый важный раздел. Честное «не сошлось, подозреваю learning rate» ценится выше, чем отчет, в котором всё идеально.

## Окружение

Python 3.11+, пакеты из `requirements.txt`. Первая работа это чистый Python, вторая на `torch`; обучение во второй идет на процессоре 10–20 минут, видеокарта не обязательна. В CI `torch` ставится без CUDA.

## Про ИИ-ассистентов

Использовать можно и нужно: как справочник и напарника. Нельзя сдавать код, который вы не можете объяснить и изменить; откуда он взялся, значения не имеет. На устной проверке ассистент закрыт.
