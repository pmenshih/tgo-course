# ТГО · Регламент лабораторных работ

Как сдаются лабораторные работы по курсу. Короткая версия: вы ведете репозиторий, тесты проверяют его сами, преподаватель выборочно задает вопросы.

## 1. Зачем это так устроено

Проверяется результат, а не присутствие: код в репозитории, который можно запустить, и ваше умение этот код объяснить и изменить. Побочный эффект: к концу курса у вас есть репозиторий с семью работами по глубокому обучению, настроенным CI и историей коммитов. Это можно показывать работодателю.

## 2. Репозиторий

1. Создайте репозиторий из шаблона курса на GitHub (ссылка на шаблон выдается на первой паре).
2. Если репозиторий приватный, преподаватель (`pmenshih`) добавлен с правами чтения. Ссылку на репозиторий пришлите преподавателю.
3. Структура фиксирована: папки `lab01` … `lab07`, в каждой код, `README.md` и то, что требует конкретная работа. Папки и файлы, которые ожидают тесты, не переименовывайте.
4. Файлы данных и веса моделей в репозиторий не кладутся. В задании к каждой работе указано, откуда они скачиваются или как генерируются.

На первом занятии часть времени отводится на вопросы по настройке репозитория, CI и окружения, дальше вы разбираетесь сами, преподаватель помогает в чате. Если с git вы раньше не работали, это ваша возможность разобраться. После первого занятия вопрос «как сделать коммит» считается закрытым.

## 3. Что значит «работа сдана»

Работа считается сданной, когда одновременно выполнены три условия.

**Тесты пройдены.** В шаблоне для каждой (кроме первой) работы есть папка `tests/` и настроенный CI. При каждом push тесты запускаются автоматически. Они проверяют воспроизводимость, а не качество модели: код выполняется от начала до конца, нужные артефакты сохраняются, метрика выше минимального порога (обычно это «заметно лучше случайного угадывания»). Зеленый статус CI по работе виден и вам, и преподавателю. Запускать тесты локально перед push настоятельно рекомендуется, команда для этого есть в README шаблона. Первая работа проверяется по README и выборочно устно.

**Есть отчет.** В папке работы лежит `README.md` из трех разделов:
- *Что сделано.* Коротко, по пунктам, без пересказа задания.
- *Что получилось.* Результаты с цифрами: метрики, время обучения, размер модели. Графики приветствуются.
- *Что не получилось и почему.* Самый важный раздел. Честное «не сошлось, подозреваю learning rate, проверить не успел» ценится выше, чем отчет, в котором всё идеально.

Отчет на один экран. Если получается длиннее, вы пересказываете задание.

**История коммитов правдоподобна.** Работа делается постепенно, и репозиторий это отражает. Формальный минимум: не менее трех содержательных коммитов на работу, разнесенных по времени. Один коммит «lab03 done» или семь коммитов за десять минут автоматически отправляют вас на обязательную устную проверку (см. раздел 5). Это не наказание, а способ убедиться, что работу делали вы.

## 4. Сроки

По каждой лабораторной одно занятие. Задание выдается на лекции, на ближайшем занятии по лабораторным разбор задания, типовые грабли, консультации. Доделываете самостоятельно.

**Мягкий дедлайн:** следующее занятие по лабораторным. К его началу работа должна быть в репозитории с зеленым CI; на этом же занятии проходит устная проверка по жребию (раздел 5). Опоздание не запрещено, но просроченная работа автоматически попадает на обязательную устную проверку вне жребия. На момент подачи заявки на профессиональный трек все уже выданные работы должны быть сданы.

**Жесткий дедлайн:** последняя пара семестра. Все семь работ сданы по условиям раздела 3, иначе допуска к экзамену нет. Для седьмой работы это единственный дедлайн.

Если CI не проходит из-за ошибки в самих тестах или в шаблоне, пишите преподавателю сразу, не ждите дедлайна. Ошибка в шаблоне не ваша вина, и дедлайн по такой работе сдвигается.

## 5. Устная проверка

На каждом занятии преподаватель вызывает 5–6 человек по жребию. Проверка занимает около пяти минут и проходит у вашего ноутбука с открытым репозиторием.

Формат один и тот же: преподаватель выбирает одну из уже сданных вами работ (не обязательно текущую) и просит изменить что-то в коде и объяснить, что изменится. Например: поменять функцию потерь, убрать слой, изменить размер батча и сказать, как это повлияет на результат и почему. Вопросы по README тоже возможны: если вы написали «не сошлось из-за learning rate», будьте готовы объяснить, почему вы так думаете.

Проверка считается пройденной, если вы ориентируетесь в собственном коде и понимаете, что он делает. Безошибочный ответ не требуется, требуется понимание.

За семестр каждый студент проходит устную проверку не менее одного раза. Кто ни разу не попал под жребий, проверяется на последней паре.

Если проверка не пройдена, работа снимается, и вы пересдаете ее на следующей паре. Вторая неудача по той же работе означает, что работу нужно переделать.

Обязательная устная проверка (вне жребия) назначается, если работа сдана после мягкого дедлайна, если история коммитов не проходит формальный фильтр из раздела 3, или если код двух студентов совпадает настолько, что это заметно без специальных средств.

## 6. Что можно и что нельзя

Можно и нужно: обсуждать задачи друг с другом, пользоваться документацией, статьями, Stack Overflow, языковыми моделями как справочником и напарником.

Нельзя: сдавать код, который вы не можете объяснить и изменить. Откуда он взялся, из чужого репозитория или из чата с моделью, значения не имеет.

## 7. Допуск и оценка

Лабораторные работы являются условием допуска к экзамену: семь работ сданы по разделу 3, устная проверка пройдена. 

Студенты профессионального трека сдают лабораторные в составе инженерной части защиты, по правилам трека.

## 8. Коротко

1. Репозиторий из шаблона, ссылка преподавателю.
2. На каждую работу: код, зеленый CI, README на один экран, нормальная история коммитов.
3. Мягкий дедлайн: следующее занятие. Жесткий: последняя пара семестра. Просрочка означает обязательную устную проверку.
4. На каждом занятии жребий, пять минут, «измени и объясни».
5. Семь сданных работ = допуск к экзамену.
