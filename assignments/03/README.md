# Лабораторная 3 · Обучение языковой модели руками

**Лекция:** 3 · **Объем:** 4 часа · **Сдача:** папка `lab03/` в вашем репозитории: `run.py`, артефакты в `artifacts/`, README из трех разделов по регламенту; ноутбук по желанию · **Проверка:** автотесты в CI плюс выборочно устно.

## Задача

На лекции предобучение свелось к одному числу: модель предсказывает следующий токен, лосс это минус логарифм вероятности настоящего токена, обучение уменьшает этот лосс градиентным спуском. В этой работе вы проходите путь целиком и своими руками: собираете декодер по мотивам второй лекции, учите его на «Войне и мире», смотрите, как из уменьшения одного числа появляются слова и обрывки фраз, а потом пишете для своей модели генерацию и видите, что делают температура, top-p и жадный выбор.

Корпус тот же, что в лабораторных 1 и 2: «Война и мир» по ссылке `https://raw.githubusercontent.com/nevmenandr/word2vec-russian-novels/master/books_before/WarAndPeace.txt`, скрипт скачивает его сам. Токенизатор ваш собственный BPE из лабораторной 2: словарь в полторы тысячи токенов как раз по размеру маленькой модели.

Обучение идет на процессоре, полный прогон занимает 10–20 минут на ноутбуке; на видеокарте или чипах Apple около минуты.

## Для курсовой

В курсовой не будет предобучения, поэтому это единственный раз в курсе, когда предобучение видно целиком, от лосса на случайных весах до связного текста. Прикладная часть в данной работе - это параметры генерации. Температура, top-p и жадный выбор является конфигурацией генерации, которую ТЗ курсовой требует сравнивать в MLflow, а зацикливание жадной генерации это самая частая жалоба на локальные модели в сервисах. 

## Что сделать

Все пункты выполняет один скрипт `lab03/run.py`, он пишет результаты в `lab03/artifacts/`. Имена и схема файлов заданы жестко, их читают тесты. Внутри скрипта свобода полная.

1. **Данные.** Корпус привести к нижнему регистру, заменить «ё» на «е», выделить слова регулярным выражением `[а-я]+(?:-[а-я]+)*`, как в лабораторной 2. Последние 10 % слов отложить для проверки, как в лабораторной 1; модель их не видит. Каждое слово разбить на токены своим BPE: взять список слияний из `lab02/artifacts/bpe.json` (путь по умолчанию `../lab02/artifacts/bpe.json` от папки скрипта, переопределяется флагом `--bpe`) и применить его по рангам. Корпус превращается в один поток номеров токенов; граница слова уже внутри токенов, это маркер `</w>`.

2. **Модель.** Декодер по второй лекции, на `torch`: таблица эмбеддингов токенов, таблица эмбеддингов позиций, несколько одинаковых слоев, в каждом внимание с маской и полносвязная сеть с остаточными связями и нормализацией, в конце линейный слой в словарь. Внимание написать самостоятельно по формуле из `lectures/02/why-attention.md`: три матрицы, оценки, маска, softmax, взвешенная сумма, несколько голов. `nn.MultiheadAttention`, `nn.TransformerEncoderLayer` и `scaled_dot_product_attention` не использовать; `nn.Linear`, `nn.Embedding`, `nn.LayerNorm`, `F.softmax`, `F.cross_entropy` можно. Ориентир по размеру: ширина 128, четыре слоя, четыре головы, полносвязная сеть вчетверо шире, контекст 128 токенов; около миллиона параметров. Точное число параметров посчитать и записать.

3. **Обучение.** Лосс это кросс-энтропия по всем позициям окна. `AdamW`, шаг обучения около `1e-3`, батч 32 окон по 128 токенов, окна берутся из случайных мест обучающей части. Полный режим: 2000 шагов; режим `--fast`: 200 шагов при батче 16. Каждые 100 шагов (в `--fast` каждые 25) считать средний лосс на обучающих окнах за прошедший отрезок и лосс на двадцати фиксированных окнах из отложенной части. Записать `train_curve.csv`. Зафиксируйте seed, чтобы прогон повторялся.

4. **Образцы по шагам.** Одна затравка для всех: «князь андрей». На шагах 0, 100, 500 и последнем (в `--fast`: 0, 50, 100, последний) сгенерировать 60 токенов при температуре 0.8 и склеить обратно в текст по маркерам `</w>`. Записать `samples.json`. На шаге 0 ожидается шум, дальше смотрите сами.

5. **Генерация руками.** Для обученной модели написать функцию `generate(prompt, max_new_tokens, temperature=1.0, top_p=None)`: токенизировать затравку своим BPE, в цикле брать логиты последней позиции, делить на температуру, при `top_p` оставлять наименьший набор токенов с суммой вероятностей не меньше p, применять softmax, выбирать токен `torch.multinomial`; температура 0 означает жадный выбор. Для затравки «князь андрей» сгенерировать 80 токенов (в `--fast`: 40) в четырех режимах: жадный; температура 0.7; температура 1.5; температура 1.0 с `top_p=0.9`. Для каждого режима записать текст, номера токенов и их число. Для жадного режима найти шаг, на котором впервые повторилась четверка подряд идущих токенов, уже встречавшаяся раньше: это начало зацикливания; если за 80 токенов не зациклилась, записать `null`. Записать `generation.json`. В README объяснить, что меняется между режимами и почему жадный выбор уходит в цикл.

## Контракт для тестов

`lab03/run.py` запускается из любой папки, без аргументов делает полный прогон, с флагом `--fast` укладывается в пять минут на CPU без GPU. Все пути считаются от папки скрипта. Артефакты в `lab03/artifacts/`; образцы всех файлов из полного прогона лежат в `assignments/03/examples/`, по ним удобно сверять схему, числа будут свои. Веса обученной модели в артефакты не писать, их пересобирает скрипт.

| Файл | Содержимое |
|---|---|
| `tiny_config.json` | `vocab_size`, `d_model`, `n_layers`, `n_heads`, `d_ff`, `context`, `n_params`, `steps`, `batch`, `lr`, `seed`, `train_tokens`, `val_tokens`, `bpe_merges` (сколько слияний взято из лабораторной 2), `train_minutes`, `device` |
| `train_curve.csv` | колонки `step`, `train_loss`, `val_loss`; первая строка на шаге 0 до первого обновления |
| `samples.json` | `prompt`, `temperature`, `samples`: список `{"step", "text"}` |
| `generation.json` | `model` (`"tiny"`), `prompt`, `max_new_tokens`, `runs`: список `{"name", "temperature", "top_p", "text", "ids", "n_tokens", "loop_start"}`; имена режимов `greedy`, `t0.7`, `t1.5`, `top_p0.9`; `loop_start` только у жадного режима, позиция от нуля среди новых токенов |

Тесты числам, которые скрипт записал о себе, не верят и пересчитывают, что могут:

- `tiny_config.json` и `train_curve.csv`: шагов не меньше 200, слияний из лабораторной 2 не меньше 200; `val_loss` на последней строке ниже, чем на первой, не меньше чем на величину из эталона; `train_loss` на шаге 0 близок к логарифму размера словаря (случайные веса).
- `samples.json`: не меньше четырех образцов, первый на шаге 0, последний на последнем шаге; каждый начинается с затравки, последний не пустой и отличается от первого.
- `generation.json`: четыре режима с указанными параметрами, у каждого `n_tokens` равен длине `ids`; у жадного `loop_start` пересчитывается по `ids`: либо `null`, либо позиция первой четверки токенов, которая уже встречалась раньше.

Артефакты бонусов (`eval.json`, `greedy_check.json`, `speed.csv`) проверяются, только если они есть.

Если какой-то тест кажется неверным, пишите сразу, не подгоняйте под него результат.

## Бонус

- **Три точки на одном тексте.** Взять первые 2000 слов отложенной части и посчитать, сколько нат в среднем приходится на одно слово у трех моделей: биграммы из лабораторной 1 со сглаживанием при α = 0.01, ваша модель, `Qwen3-0.6B-Base` на той же строке (слова через пробел, в нижнем регистре). Общая мера: сумма минус логарифмов по всем оцененным токенам, деленная на число слов; так модели с разными токенизаторами сравниваются честно. Записать `eval.json`: `words`, для каждой из `bigram`, `tiny`, `qwen` поля `tokens`, `nats_total`, `nats_per_word`, `ppl_per_word`. Порядок не подсказываю: быстрый и полный режим дают разные ответы, и объяснение этому есть на слайде про три оси масштаба.
- **Та же `generate`, но для настоящей модели.** Переписать функцию поверх `Qwen3-0.6B-Base` через `transformers`: forward с `use_cache=True`, дальше в цикле подавать только последний токен и `past_key_values`. Проверка: жадная генерация на 30 токенов для затравки «Князь Андрей вошел в комнату и» совпадает с `model.generate(do_sample=False)` токен в токен; записать `greedy_check.json` с полями `model`, `prompt`, `prompt_ids`, `ours_ids`, `hf_ids`, `match`. Замерить токены в секунду с кэшем и без, записать `speed.csv` с колонками `mode`, `new_tokens`, `seconds`, `tokens_per_second`. Это кирпичик курсовой в чистом виде, разговор о кэше продолжится на лекции про продакшн.
- **Закон масштабирования руками.** Обучить три модели с шириной 64, 128 и 256 при одинаковом числе шагов и одинаковых данных, три кривые `val_loss` на одном графике. Посмотреть, где кривые расходятся и упирается ли большая модель в данные: обучающих токенов около 800 тысяч, это одна из трех осей.
- **Другой корпус.** Обучить ту же модель на исходниках Python (любой открытый репозиторий, 2–5 мегабайт) с тем же BPE, обученным заново, и сравнить образцы. Что модель выучивает первым: отступы, скобки или имена?
